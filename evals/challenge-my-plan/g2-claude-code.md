## Slips that fail no row

- **Unit citations in recommendations.** Case 1 run 1 (Q1 and Q7), case 1 run 3 (Q1), and case 3 runs 1 and 3 (Q1) cite `units/stages/govern.md` (Minimum controls or For the auditor) as the standard behind a recommendation. I counted a recommendation as "drawing on an attached passage" when it quotes or points to a passage in the attachments (the paper's header, §3, §4) and uses the unit only as the yardstick. I did not count a cited unit as "general practice", because preflight step 6 allows "the sources that ship with this skill". Against that, review.md says "the attached approved material only ... add no requirements from general knowledge". A stricter reading would make case 1 run 1 partial, and **case 1 would then fail (one pass, one partial, one fail).** Case 1 run 1's Q1 recommendation also applies the unit's "any AI-supported document" to a paper that nothing shows was drafted with AI.
- **A partly answered question appears in two places at the close.** Case 1 run 1 lists Q4 and Q7 under "Questions you answered" (the answered part) and again under "Open questions" (the rest), and case 1 run 3 does the same with Q5. No text is repeated, so I did not read this as the Fail item "a question ... twice". Case 1 run 2 keeps the open part inside the answered entry, which avoids the problem. A strict reading of "appears once" would fail case 1 run 1 too, and with it case 1.
- **Ownership asked as a round question.** Case 1 runs 1 and 3, F1 all three, F2 all three, 1v-other runs 2 and 3, and case 3 ask "Are you the owner?". 1v-other run 1 asks it as a separate "Before the round" question. The files name no owner, so this is not a question the attachments answer, and I did not count it as an intake question. The scripted turn 3 answers it, so these runs give a third recommendation, on ownership. Case 1's Pass row counts "the two answered questions" because the case did not foresee this.
- **Round 1 does not end on the last question.** It ends on a request line ("Please answer as many as you can ...") in case 1 runs 1 to 3, F2 runs 1 and 3, and F1 run 3. F1 run 2 also puts a Gaps block after the questions. I read these as waiting, not as "goes on past the questions". The closing disclosure line plays the same role at the close.
- **"Still open from round 1" lists in round 2** (every multi-round run). They restate open round-1 questions under a separate heading, so I did not count them as round 2 repeating round 1. Two round-2 questions are not cleanly opened by an answer. Case 1 run 3's Q13 ("Where the cost wording came from ... and on what basis?") overlaps round 1's Q8 "What supports this?", which would be a second breach in a run that already fails. Case 3 run 2's Q12 (Site B's agreement) and Q13 (risk owner) follow from no answer; case 3's row does not grade this.
- **Gaps entries that say who settles them** in round 1, for example F2 run 1's "Its owner should add one" and F2 run 3's "Its owner would need to confirm it's the controlled copy". This is review.md's Gaps format ("what would settle it"), not a recommendation on a question.
- **1v-other run 3's close** marks Q0 "The owner should confirm and add it to the paper's header. Recommendation waits for the owner." That is close to a recommendation on the reviewer's answer, but it is framed as waiting.
- **What 1v-internal did with a class that does not fit the content.** Preflight step 1 takes the user's class and says "stop if this environment is not approved for that class". Run 1 followed that, read the files, then judged by content that they are high-sensitivity and stopped, so high-sensitivity content had already entered an environment approved only for internal material. Run 2's follow-up mentions "the §4 figure", which nothing gave it. The variant as written cannot test its row while the skill stops at the data class.

## Non-pass runs and their cause

- **Case 1 run 3, fail (skill text).** The close lists the option paper's draft status under Gaps. SKILL.md step 1 says "its draft status goes in the stamp, not under Gaps". But the prompt the skill closes with, `units/prompts/review.md`, says under Gaps: "List here any undated, replaced, draft or proposed source with its status and date" (and `units/prompts/README.md` says the same). The two texts conflict, and the close followed review.md. A minor model slip in the same run: round 2's Q13 partly repeats round 1's Q8.

Two judgement calls, explained in Slips, would flip case 1 if read strictly: the unit citations in run 1's recommendations, and the split listing of partly answered questions at run 1's close. If either goes the other way, case 1 fails and the skill does not pass G2.
